# US-304 - Acces securise aux pieces justificatives

**Labels** : `epic:3`, `type:backend`, `type:security`, `type:infra`
**Priorite** : Critique
**Story Points** : 5
**Dependance** : US-302 (upload des documents et stockage S3)

## User story

En tant que responsable securite, je veux que les pieces justificatives des dossiers soient stockees dans un bucket prive et accessibles uniquement apres authentification et autorisation, afin de proteger les donnees personnelles.

## Contexte technique actuel

- Le bounded context concerne est `backend/src/dossiers/`.
- L'entite document est `src.dossiers.domain.entities.document.Document`.
- L'entite dossier est `src.dossiers.domain.entities.dossier.Dossier` et expose `is_owned_by(user_id)`.
- Le port de stockage est `src.dossiers.domain.ports.document_storage_port.DocumentStoragePort`.
- L'adaptateur S3 est `src.dossiers.infrastructure.adapters.s3_document_storage.S3DocumentStorageAdapter`.
- Les ports de persistance sont `DocumentRepository` et `DossierRepository`.
- L'authentification est fournie par `src.api.dependencies.get_current_user`.
- Le projet ne comporte actuellement que les roles `CLIENT` et `ADMIN`. Le terme "conseiller" est donc traduit par `ADMIN` pour ce ticket. La creation de roles metier supplementaires est hors perimetre.
- Le routeur dossiers existe dans `src/api/rest/dossier_routes.py`, mais il doit etre enregistre dans `src/api/main.py` pour exposer ses routes.

## Criteres d'acceptation

1. Un appel anonyme direct vers l'URL S3 d'un document est refuse par S3 avec HTTP 403.
2. Le bucket des documents n'autorise pas les acces publics et refuse les requetes non TLS.
3. Un utilisateur authentifie proprietaire du dossier peut demander une URL de consultation.
4. Un utilisateur authentifie avec le role `ADMIN` peut demander une URL de consultation pour tout dossier.
5. Un utilisateur `CLIENT` qui n'est pas proprietaire recoit HTTP 403.
6. Un appel sans authentification vers l'endpoint de consultation recoit HTTP 401.
7. Une URL de consultation est une URL pre-signee GET avec une expiration de 60 secondes.
8. Un dossier ou un document inexistant recoit HTTP 404.
9. Un document existant mais rattache a un autre dossier recoit HTTP 404.
10. L'URL S3 et la cle S3 ne sont jamais exposees par un endpoint public sans controle d'acces.

## Contrat API

```http
GET /api/v1/dossiers/{dossier_id}/documents/{document_id}/view-url
Authorization: Bearer <token>
```

Reponse `200 OK` :

```json
{
  "url": "https://s3.../presigned-url",
  "expires_in": 60
}
```

Erreurs :

- `401 Unauthorized` : token absent, invalide ou utilisateur introuvable.
- `403 Forbidden` : utilisateur authentifie mais non autorise.
- `404 Not Found` : dossier inexistant, document inexistant ou document non rattache au dossier fourni.

## Tache 1 - Finaliser la securite du bucket S3

- Verifier qu'aucun ACL `public-read` n'est utilise et que le website hosting n'est pas active.
- Verifier que les acces applicatifs utilisent uniquement des URLs pre-signees et des credentials IAM cote serveur.
- Realiser en staging un test anonyme attendu en HTTP 403, lorsque l'environnement AWS ou S3 compatible est disponible.

### Definition of done

- Le Terraform conserve le blocage public, le chiffrement SSE-S3 et l'obligation TLS.
- La politique documentee correspond a la configuration Terraform effective.

## Tache 2 - Ajouter le service d'autorisation applicatif

**Fichier a creer** : `backend/src/dossiers/application/services/authorization.py`

**Tests a creer** : `backend/tests/unit/dossiers/application/services/test_authorization.py`

Ajouter une fonction publique strictement typee :

```python
from src.auth.domain.entities.user import User
from src.auth.domain.value_objects import Role
from src.dossiers.domain.entities.document import Document
from src.dossiers.domain.entities.dossier import Dossier


def can_access_document(user: User, document: Document, dossier: Dossier) -> bool:
    """Indique si l'utilisateur peut consulter le document du dossier."""
    if document.dossier_id != dossier.id:
        return False
    return dossier.is_owned_by(user.id) or user.role == Role.ADMIN
```

La verification `document.dossier_id == dossier.id` protege l'appelant contre une association incoherente. La regle d'appartenance du dossier reste dans `Dossier.is_owned_by`; la comparaison du role reste dans la couche application.

Tests unitaires minimaux :

- proprietaire `CLIENT` : `True` ;
- `ADMIN` non proprietaire : `True` ;
- `CLIENT` tiers : `False` ;
- document rattache a un autre dossier : `False`.

## Tache 3 - Generer une URL de consultation dans l'adaptateur S3

**Port a modifier** : `backend/src/dossiers/domain/ports/document_storage_port.py`

Ajouter :

```python
async def generate_download_url(
    self,
    s3_key: str,
    expires_in: int = 60,
) -> str:
    """Genere une URL pre-signee GET pour consulter un document."""
    ...
```

**Adaptateur a modifier** : `backend/src/dossiers/infrastructure/adapters/s3_document_storage.py`

Implementer `generate_download_url` en conservant le modele asynchrone deja utilise par `generate_upload_url` : l'appel boto3 synchrone doit etre execute dans un executor. L'appel boto3 attendu est equivalent a :

```python
self._client.generate_presigned_url(
    ClientMethod="get_object",
    Params={"Bucket": self._bucket_name, "Key": s3_key},
    ExpiresIn=expires_in,
)
```

Le defaut de cette methode est `60` secondes. Le defaut d'upload reste `300` secondes et ne doit pas etre modifie par ce ticket.

**Test unitaire a ajouter** dans la suite existante de l'adaptateur S3 :

- `ClientMethod == "get_object"` ;
- `Bucket == "m-motors-documents"` ou valeur fournie par `Settings` ;
- `Key == s3_key` ;
- `ExpiresIn == 60` par defaut et respecte lorsqu'une autre valeur est explicitement fournie.

## Tache 4 - Exposer l'endpoint de consultation

**Schema a modifier** : `backend/src/dossiers/application/schemas/document_schemas.py`

Ajouter :

```python
class ViewUrlResponse(BaseModel):
    """Reponse contenant une URL temporaire de consultation."""

    url: str
    expires_in: int
```

**Route a modifier** : `backend/src/api/rest/dossier_routes.py`

Ajouter une route relative au prefixe existant `APIRouter(prefix="/api/v1/dossiers", ...)` :

```http
GET /{dossier_id}/documents/{document_id}/view-url
```

La route doit :

1. dependre de `get_current_user` depuis `src.api.dependencies` ;
2. construire `SqlAlchemyDossierRepository(session)`, `SqlAlchemyDocumentRepository(session)` et `S3DocumentStorageAdapter(get_settings())`, comme les routes documents existantes ;
3. recuperer le dossier via `DossierRepository.get_by_id` ;
4. recuperer le document via `DocumentRepository.find_by_id` ;
5. retourner `404` si l'un des deux n'existe pas ;
6. retourner `404` si `document.dossier_id != dossier_id` ;
7. appeler `can_access_document(current_user, document, dossier)` et retourner `403` si le resultat est faux ;
8. appeler `generate_download_url(document.s3_key, expires_in=60)` ;
9. retourner `ViewUrlResponse(url=url, expires_in=60)`.

La dependance `get_current_user` garantit le `401` avant la logique metier lorsqu'il n'y a pas de bearer token valide.

**Enregistrement obligatoire** : ajouter le routeur dossiers dans `backend/src/api/main.py`, par exemple avec `from src.api.rest.dossier_routes import router as dossier_router` puis `app.include_router(dossier_router)`. Sans cette etape, l'endpoint n'est pas expose par l'application.

### Tests d'integration/e2e

Etendre `backend/tests/e2e/api/test_dossier_documents_api.py` ou creer un fichier voisin dans le meme dossier pour couvrir :

- proprietaire `CLIENT` : `200`, champ `url`, `expires_in == 60` ;
- `ADMIN` : `200`, champ `url`, `expires_in == 60` ;
- `CLIENT` tiers : `403` ;
- sans authentification : `401` ;
- dossier inexistant : `404` ;
- document inexistant : `404` ;
- document rattache a un autre dossier : `404` ;
- verification du mock de `DocumentStoragePort.generate_download_url` avec la cle du document et `60` secondes.

Le test d'expiration reelle de S3 est optionnel en integration cloud. Le test local doit verifier le contrat d'appel et la valeur `ExpiresIn`; il ne doit pas dependre d'une horloge distante ou d'un bucket AWS reel.

## Definition of done globale

- Les noms de fichiers et imports correspondent a l'arborescence actuelle.
- Le bucket reste prive, chiffre et accessible uniquement en TLS.
- Le port, l'adaptateur, le service d'autorisation et l'endpoint sont couverts par des tests adaptes a leur couche.
- Le routeur dossiers est effectivement enregistre dans l'application FastAPI.
- Les commandes de validation backend passent : `ruff check`, `black --check` et les tests pytest concernes.
- La documentation OpenAPI generee par FastAPI expose la route avec les reponses `200`, `401`, `403` et `404`.

## Points explicitement hors perimetre

- Creation de roles `CONSEILLER` ou `FINANCIER` : le modele actuel ne connait que `CLIENT` et `ADMIN`.
- Chiffrement applicatif fichier par fichier : le ticket couvre le chiffrement serveur S3 deja choisi (SSE-S3), pas un chiffrement cote client ou KMS.
- Modification des URLs d'upload, dont l'expiration reste a 300 secondes.
- Purge RGPD des documents, couverte par US-305.
